## Blocking title route

The following sequence fails on Chromium, Firefox and WebKit.

1. Open `https://beta.parkscomputing.com/?launcher=closed` in a fresh context and wait for host initialization.
2. Click the Parks Computing title returned by `pudlMenubar.launcherButton({ visible: true })`.
3. Observe that the catalog remains closed and focus remains on the title.

The generated title has `data-menu-id="site"`, but no `popovertarget` or `aria-controls`; its popup type still says menu. The menubar retains `data-menubar-launcher="site-launcher"`, and the catalog has become a popover through `pudlLauncher.enhance`. The menu bar initialized before that presentation change. Previously, the title was the controller's primary invoker and its attributes were synchronized by the controller. The new permanent invoker receives that synchronization instead.

The frozen `pudl-menubar.js` title constructor supplies native targeting only when the catalog is already a popover. Its pointer path subsequently returns for a popup launcher because it expects native activation. The live trace records no launcher request or popup transition when the incomplete title is clicked. This identifies an opener synchronization gap across initialization and presentation changes. The host has not patched generated menu DOM or installed another click handler.

Upstream should synchronize every retained launcher route when the catalog changes between pane and popup presentation. Acceptance must include initially embedded markup without a popover attribute, initial closed mode, pane-to-popup and popup-to-pane transitions, both openers, keyboard/hamburger routing and touch browsing focus. A replacement frozen candidate is required before host acceptance.
